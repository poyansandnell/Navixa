Apple kräver permanent account deletion direkt i appen.

Som vanlig inloggad användare ska jag kunna gå:

`Profile → Settings → Account → Delete Account`

Placera `Delete Account` tydligt i Account-sektionen.

Det får inte:
- endast finnas i kod
- endast finnas i admin
- vara dolt bakom ett ovanligt flöde
- kräva supportkontakt

Det ska fungera för vanliga användare i iOS-appen.

- radera användarens konto permanent
- radera/anonymisera relevant data

## 2. REPORT + BLOCK SKA VARA LÄTTA ATT HITTA

Jag kan inte hitta var man blockerar en användare.

På varje annan spelares profil ska det finnas en tydlig meny, exempelvis `•••`, med:

- Report player
- Block player

Alternativt kan knapparna ligga direkt på profilen, men de måste vara lätta att hitta.

Jag ska kunna göra:

`Other player's profile → ••• → Report player`

och:

`Other player's profile → ••• → Block player`

### Report player

Visa kategorier:
- Abusive or offensive behavior
- Harassment
- Inappropriate username/profile
- Cheating
- Spam
- Other

Tillåt valfri fritext.

Efter submit:
- visa tydlig confirmation
- skapa moderation/report-record server-side

### Block player

Visa confirmation:

`Block [name]?`

Förklara att personen inte längre ska kunna interagera med användaren.

Efter blockering ska ändringen märkas direkt.

Den blockerade användaren ska bland annat:
- inte kunna skicka friend requests
- inte matchas mot användaren
- inte synas i relevanta sociala listor/sökresultat för den blockerande användaren
- inte kunna initiera privata matcher/interaktioner där block ska gälla

Blockeringen ska också skapa ett moderation-event/report så developer blir aware enligt Apples Guideline 1.2.

## 4. NAMNSYSTEMET MÅSTE FIXAS

Dubbelkolla hela username/display-name-flödet.

### Krav

Användare ska kunna använda namn med:

- mellanslag
- svenska bokstäver: å, ä, ö
- stora och små bokstäver
- vanliga internationella Unicode-bokstäver

Exempel som ska accepteras:

`Poyan Sandnell`

`Åsa Lind`

`Björn Öberg`

`Måns`

`José García`

Använd inte en gammal regex som endast tillåter `[A-Za-z0-9_]`.

### Unikhet

Alla namnförslag som systemet automatiskt genererar måste vara LEDIGA innan de visas eller sparas.

Systemet får aldrig föreslå ett namn som redan är upptaget.

Kontrollera uniqueness SERVER-SIDE, inte bara i klienten.

Hantera race conditions: två användare ska inte kunna få samma namn om de sparar samtidigt.

Använd databasens unique constraint/index som slutlig garanti.

### Normalisering

Unikhetskontrollen ska vara robust.

Minst:
- trimma leading/trailing whitespace
- kollapsa flera mellanslag till ett om det är produktbeslutet
- Unicode-normalisera, t.ex. NFC
- jämför namn case-insensitive för uniqueness

Exempel:

`Poyan Sandnell`

och

`poyan sandnell`

ska INTE kunna bli två olika unika namn om systemet betraktar dem som samma användarnamn.

På samma sätt ska Unicode-normalisering inte göra att visuellt samma `Åsa` kan registreras dubbelt genom olika Unicode-representationer.

Behåll däremot användarens snygga originalstavning för visning.

### Namnförslag

När appen föreslår namn:

1. Generera kandidat.
2. Normalisera kandidaten.
3. Kontrollera mot databasen.
4. Om upptagen: generera nästa.
5. Visa endast kandidater som är bekräftat lediga.

Generera flera unika alternativ, inte samma namn med risk för krock.

Om exempelvis `Poyan Sandnell` redan finns kan systemet föreslå något som:

`Poyan Sandnell 2`

eller annan produktmässigt bra variant, men endast efter server-side availability check.

Undvik fula eller slumpmässiga suffix om bättre alternativ finns.
